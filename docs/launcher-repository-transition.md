# NexaCL 仓库与发行源迁移

- 源码、反馈和后续开发指向 `Nexa-MC/NexaCL`；已签名发行构件优先读取 `Nexa-MC/NexaCL-Update`。
- 网页发布目录合并更新源、源码发行页和 `Nexa-MC/PCL-N` 历史发行页，同一版本优先保留更新源。旧 `PCL-N-Edition/PCL-N` 链接继续识别，历史 URL 不改写为新仓库中不存在的构件。
- Worker 同源代理、浏览器直连回退、快照生成共用目录校验与合并逻辑。单个源不可用时保留其他有效源；所有源失败才使用已保存快照。边缘缓存使用新的目录标识，浏览器保留一分钟缓存与请求合并。
- 六个平台组合从真实发布资源中选包；不根据版本号猜测下载地址。下载完成页仅接受上述固定仓库的构件及其对应签名。桌面安装器的签名验证与更新准入不由网页替代。
- 首页与下载页使用 NexaCL Firefly，当前版本由公开发行目录显示。说明全球正版资格要求与中国大陆本体下载限制；启动器下载和既有完整本地安装保持可用。
- `pcln.top`、Auth/API service bindings、数据库、mTLS 和已签署法律文档的标识/哈希保持现有服务契约。管理员已关联 Issue 的数字 ID 仍属于原仓库，不能改成新仓库下同号 Issue。

验证：多源优先级与去重、源故障与旧版本兼容、伪造链接拒绝、请求缓存和取消、Worker 路由/缓存，以及生产类型检查、静态构建和 Worker dry-run。

生产发布使用 `Deploy NexaCL Web Worker` 手动工作流，输入已验证的 `master` 完整提交 SHA，复用现有 `cloudflare-pages` 环境中的 Cloudflare 凭据，同时部署静态资源与同源发布代理。历史 Pages 自动构建不能替代 `nexa-web` Worker 部署；不需要改动 Auth/API 或数据库。
