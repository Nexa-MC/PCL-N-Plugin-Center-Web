## 2. 适用范围

本政策适用于 Nexa Cloud 实际开放的：

- 网站；
- NexaStore；
- Nexa 账户；
- 组织和开发者功能；
- Cloud+；
- 云空间；

相关功能实际启用前，我们会按照需要更新本政策并完成必要告知或同意流程。

## 3. 我们处理哪些信息

### 3.1 账户和第三方登录

Nexa 当前支持：

- GitHub；
- Microsoft；
- Google。

根据你选择的提供商，我们可能处理：

- 身份提供商名称；
- 该提供商返回的稳定账户标识；
- 显示名；
- 用户名或基本个人资料；
- 邮箱地址；
- 身份绑定创建和更新时间。

当前 OAuth 配置主要请求：

**GitHub**

- `read:user`
- `user:email`

**Microsoft**

- `openid`
- `profile`
- `email`
- `User.Read`

**Google**

- `openid`
- `profile`
- `email`

Nexa 不接收这些服务的账户密码。

我们不会仅因两个第三方账户返回相同邮箱而自动合并 Nexa 账户。

如果未来需要新增 Xbox、Minecraft 或其他权限，我们会在实际启用前更新相应告知，而不会将未来权限视为本次授权的一部分。

### 3.2 会话和身份安全信息

为了维持登录和保护账户，我们处理：

- 会话随机凭据的哈希；
- 会话范围；
- 创建和到期时间；
- OAuth state 和 nonce；
- 登录成功或失败；
- 身份绑定和解绑；
- 限流状态；
- 安全审计信息。

当前主要必要 Cookie 包括：

| Cookie             | 用途                 | 大致有效期 |
| ------------------ | ------------------ | ----: |
| `nexa_console`     | 普通控制台会话            | 24 小时 |
| `nexa_staff`       | 内部运营会话             |  1 小时 |
| `nexa_oauth_state` | 防止 OAuth 登录请求伪造和重放 | 10 分钟 |

这些 Cookie 主要采用 HttpOnly、Secure 和 SameSite 等安全属性。

Web 页面使用的短期 API 访问令牌原则上仅保留于当前页面内存，不作为持久浏览器存储。

### 3.3 用户、组织和开发者资料

使用相应功能时，我们可能处理：

- Nexa 内部用户 ID；
- 显示名；
- 公开头像或资料；
- 组织名称；
- 成员及角色；
- 发布者身份；
- 项目和资源归属；
- 管理和审核状态。

被明确标记为公开的发布者和资源资料可能向其他用户或访客展示。

### 3.4 NexaStore 内容

当开发者提交资源时，我们可能处理：

- 资源名称和说明；
- 图标；
- 分类；
- 版本；
- 许可证；
- 兼容信息；
- 权限清单；
- 依赖；

- 哈希；

- 审核记录；
- 发布和撤销状态。

草稿、隔离文件、审核证据和其他非公开资料不会仅因上传而自动成为公开内容。

### 3.5 Cloud+ 和云存储

当相关功能实际开放时，我们可能处理：

- 套餐；
- 当前容量；
- 使用量；
- 文件对象和元数据；
- 上传、读取、删除状态；
- 配额预留；
- 同步错误；
- 数据恢复状态。

我们不会仅为了“未来可能提供云服务”而提前读取本地文件。

### 3.6 付款、订阅和订单

当你购买 Nexa 自营服务时，我们可能处理：

- 商品和套餐；
- 价格；
- 币种；
- 订单号；
- 付款服务商订单标识；

- 试用资格状态；
- 订阅状态；
- 续费和取消状态；
- 退款和争议状态。

银行卡号等完整付款凭据通常直接由实际付款或 Merchant of Record 服务商处理，Nexa 不需要自行保存完整银行卡数据。

对于通过 Paddle 完成的 Nexa 自营交易，Paddle 作为 Merchant of Record 会按照其自己的交易条款和隐私规则处理完成交易所需的数据。

第三方付费 Marketplace 在 v1.0 阶段不开放，因此不会因 Marketplace 计划而提前采集开发者付款结算资料。

### 3.7 支持、举报和申诉

你联系我们时，我们可能处理：

- 截图；

## 4. Nexa Desktop 遥测

Nexa 客户端使用分级遥测。

### 4.1 必要遥测

为了掌握客户端基本运行、更新和重大故障情况，以下事件被分类为必要遥测：

- `app.started`
- `app.failure`
- `update.checked`
- `rollout.checked`

其字段限制为低基数技术信息，例如：

- Nexa 版本；
- 操作系统；
- CPU 架构；
- 成功、失败、取消等结果；
- 事件时间。

当前遥测协议不会主动附加：

- Nexa 账户 ID；
- 稳定设备或安装 ID；
- Minecraft 用户名；
- 本地文件路径；
- 自由文本日志正文。

Cloudflare 等网络基础设施在处理网络连接时仍可能在边缘节点暂时接触 IP 等网络层信息。

### 4.2 诊断遥测

稳定版本中，诊断遥测由用户设置控制。

Alpha、Beta、CI 等预发布构建可以将诊断遥测作为参与测试所必需的条件。如果你不希望提供这些诊断信息，应使用允许关闭诊断遥测的正式稳定版本。

诊断遥测可能包括：

- 游戏进程开始与退出结果；
- 任务开始与完成结果；
- 功能类别使用情况；
- 网络请求耗时；
- Nexa 内存占用；
- CPU 使用情况；
- JVM 启动时间；
- JVM 峰值工作集；
- Java 主版本；
- classpath 项目数量；
- Java heap 配置；
- 渲染距离；
- 模拟距离；
- FPS 上限；
- 图形设置；
- VSync；
- 全屏状态；
- Minecraft 版本；
- Loader 类型和版本；
- 已启用 Mod 的 ID 和版本；
- Mod 元数据格式；
- 有限数量的 Mod 依赖及版本范围；
- 符号化异常类型；
- 最多有限数量的符号化堆栈帧。

Nexa 不将完整自由文本错误日志作为普通遥测上传。

每次诊断运行使用随机 run ID 关联同一次运行中的样本，该 ID 不作为稳定设备身份使用。

- 网站分析；

## 7. 我们向谁提供或委托处理信息

### 7.1 Cloudflare

Nexa 主要使用 Cloudflare 提供：

- CDN 和网络边缘；
- Workers；
- D1；
- R2；
- 安全和基础设施；
- 受限的运行监控。

Nexa 的运行日志配置采取采样和字段最小化原则，普通运行监控不作为完整业务审计系统。

付款、退款、管理操作、条款接受、安全撤销等关键业务事实由 Nexa 自己的业务记录和审计记录保存，而不是依赖抽样日志。

根据你的选择，我们与：

- GitHub；
- Microsoft；
- Google

交换完成登录和身份绑定所必要的信息。

仅在 Nexa 自营产品实际通过 Paddle 销售时适用。

Paddle 作为 Merchant of Record 处理订单、付款、税务、订阅及相关交易数据。

Nexa 不将 Paddle 作为第三方 NexaStore Marketplace、开发者分账或广告业务的默认支付工具。

### 7.4 电子邮件服务

我们会使用配置于 `pcln.top` 域名的电子邮件服务发送：

- 支持回复；

实际使用的电子邮件服务商会列入 Nexa 公开的服务商清单。

### 7.5 法定披露

在法律要求、有效执法请求、司法程序或保护用户及平台重大合法权益所必需的情况下，我们可能依法提供必要信息。

我们不会因为收到普通私人请求就任意披露用户数据。

## 8. 国际和跨境处理

Nexa 的基础设施及第三方身份、付款服务可能在中国大陆境外处理数据。

因此，中国大陆用户的数据可能涉及个人信息跨境提供。

在适用法律要求时，我们将：

- 明确相关接收方和处理目的；
- 采取数据最小化；
- 完成必要的个人信息保护影响评估；
- 取得法律要求的单独同意；
- 履行适用的数据出境安全评估、标准合同、认证或其他程序。

如果某项跨境处理的必要条件尚未满足，我们可以暂时限制对应功能或地区。

## 9. 数据保存期限

我们根据数据类型采用不同期限，而不是统一永久保存。

| 数据类别                          | 一般保存规则                                                 |
| ----------------------------- | ------------------------------------------------------ |
| OAuth state / nonce           | 约 10 分钟有效，过期后尽快清理                                      |
| 活动账户资料                        | 账户有效期间                                                 |
| 注销后的普通 Profile                | 7 天注销冷静期结束并最终确认后删除或匿名化                                 |
| 有效 Console Session            | 最长约 24 小时                                              |
| 有效 Operations Session         | 最长约 1 小时                                               |
| 失效会话                          | 删除会话 token hash；必要时仅保留匿名安全事件                           |
| 已解绑 OAuth Identity            | 完成解绑后删除相应身份映射                                          |
| 安全及访问日志                       | 一般不超过 6 个月，法律另有要求或存在安全案件除外                             |
| 未提交资源草稿                       | 发布者主动删除或账户/项目终止时处理                                     |
| 失败上传和普通隔离文件                   | 最长约 7 天                                                |
| 确认恶意的二进制文件                    | 原始二进制尽快删除；仅保留必要 hash 和案件证据                             |
| 被新版本取代的普通制品                   | 一般最长约 30 天                                             |
| 发布 hash、签名、审核和审计记录            | 一般最长约 5 年                                              |
| 已关闭的一般支持工单                    | 一般约 90 天                                               |
| `diagnostic.run` 原始诊断样本       | 30 天                                                   |
| `diagnostic.mods` 原始 Mod 清单诊断 | 30 天                                                   |
| 错误符号分组                        | 180 天                                                  |
| 遥测日聚合                         | 13 个月                                                  |
| 数据库及对象备份                      | 30 天滚动                                                 |
| 订单、支付、退款和交易记录                 | 至少满足适用法律、税务、售后及争议处理要求；适用电子商务平台义务时，自交易完成之日起不少于法律规定的最低期限 |

当数据涉及正在处理的：

- 退款；
- chargeback；
- 知识产权投诉；
- 欺诈；
- 安全事件；
- 诉讼；
- 监管调查

时，相关必要信息可以在案件处理所需期间延长保存，并限制用途。

## 10. 备份与删除

Nexa 的备份采用最长约 30 天的滚动策略。

正常数据被删除后，旧备份可能在轮换周期内暂时仍包含历史副本，但这些副本：

- 不用于恢复正常业务访问；
- 限制访问；
- 随备份周期覆盖。

如果发生系统恢复，我们会重新应用删除或注销标记，避免已经删除的普通账户数据因恢复旧备份而重新成为活动数据。

根据适用法律，你可以请求：

- 知悉个人信息处理情况；
- 查阅；
- 复制；
- 更正；
- 补充；
- 删除；
- 撤回基于同意的处理；
- 注销账户；
- 对某些处理提出限制或异议；
- 获取适用的数据可携带副本；
- 对重要自动处理结果要求解释或人工处理。

隐私请求：

`privacy@pcln.top`

我们可能采取与风险相称的方式确认请求人对相关账户或联系方式具有控制权，但不会无必要地要求额外敏感证件。

## 12. 账户注销

账户注销入口：

`/account/delete`

注销申请设有 7 天冷静期。

冷静期结束并最终生效后，我们将：

- 撤销会话；
- 删除身份绑定；
- 删除或匿名化普通账户 Profile；
- 关闭正常账户访问；
- 根据需要处理所属组织和资源。

如果你是组织唯一所有者或拥有仍需维持数据库完整性的发布记录，相关对象可以被转移至不可登录的系统保管状态。

这些资源将立即从公开目录下架。

依法必须保留的：

- 订单；
- 退款；
- 财务；
- 安全；
- 审核；
- 投诉；
- 争议

记录不会仅因为账户注销而被违法删除，但会与普通账户使用分离，并限制用于对应法定义务或案件处理。

## 13. 未成年人

Nexa 不采用一个固定全球数字替代各地区不同的年龄规则。

用户应同时满足：

- 所在地法律；
- 使用的 Microsoft、Minecraft 或其他第三方账户规则；
- Nexa 相应功能的合同能力要求。

依法需要监护人批准时，应由监护人完成相应批准。

对于中国大陆不满十四周岁的儿童，处理其个人信息依法适用特别保护要求。

如果 Nexa 尚未提供某地区法律要求的监护人同意或儿童保护流程，相应未成年人不得绕过限制注册或使用该账户功能。

## 14. 信息安全

我们采用与服务风险相适应的措施保护数据，包括：

- HTTPS；
- HttpOnly / Secure Cookie；
- OAuth state 和 nonce；
- 最小权限；
- 会话隔离；
- 普通用户和内部运营会话分离；
- 文件隔离；
- 哈希和签名验证；
- 受限扫描；
- 访问控制；
- 审计；
- 备份；
- 安全撤销。

不存在能够保证任何在线系统绝对安全的技术。

如果发生或可能发生个人信息泄露、篡改或丢失，我们将按照适用法律采取补救、记录、评估、报告和通知措施。

## 15. AI

v1.0 当前不默认将私人用户内容发送给第三方通用 AI 模型用于审核、客服分析或训练。

如果未来启用第三方 AI 能力，我们会在启用前说明：

- 提供商；
- 发送哪些数据；
- 用途；
- 处理地区；
- 保存期限；
- 是否用于训练；
- 用户可以采用的人工路径；
- 适用的同意或其他法律依据。

Cloud+ 中出现“AI 配额”或相关商品描述本身，不意味着用户数据已经发送给任何 AI 提供商。
